# ResKit 插拔式改造 - 更新日志

## 🎯 改造目标

让 ResKit 真正实现"插拔式"设计，可以放置在项目的任意位置，自动适配路径和命名空间。

## ✨ 主要改进

### 1. 动态路径管理

**新增文件**：`Editor/ResKitPathHelper.cs`

**功能**：
- 通过查找 `EURes.asmdef` 文件自动定位模块根目录
- 提供所有路径的动态获取方法
- 根据模块位置自动计算命名空间

**API**：
```csharp
ResKitPathHelper.GetModuleRoot()      // 获取模块根目录
ResKitPathHelper.GetNamespace()       // 获取命名空间
ResKitPathHelper.GetResourcesPath()   // 获取 Resources 路径
ResKitPathHelper.GetSettingsPath()    // 获取配置文件路径
ResKitPathHelper.GetEditorPath()      // 获取 Editor 路径
ResKitPathHelper.GetScriptPath()      // 获取 Script 路径
ResKitPathHelper.GetTemplatesPath()   // 获取模板路径
```

### 2. 消除硬编码路径

**修改文件**：
- `Editor/ResKitEditorWindow.cs` - 所有路径改为动态获取
- `Editor/ResServerConfigEditor.cs` - 配置路径改为动态获取

**改造前**：
```csharp
private const string SETTINGS_PATH = "Assets/EUFramework/Resources/ResKitSettings";
string prefabPath = "Assets/EUFramework/Resources/ResKitUI/ResKitUserOpePopUp.prefab";
```

**改造后**：
```csharp
private static string SETTINGS_PATH => ResKitPathHelper.GetSettingsPath();
string prefabPath = Path.Combine(ResKitPathHelper.GetResourcesPath(), "ResKitUI/ResKitUserOpePopUp.prefab");
```

### 3. 灵活的 Resources 路径

**运行时代码无需修改**：
- `Resources.Load()` 使用相对路径，Unity 会自动识别任何位置的 Resources 文件夹
- 配置文件和 UI 预制体可以随模块一起移动

### 4. 命名空间自动生成

**规则**：排除 `Assets` 后的文件夹路径，用点号连接

**示例**：
- `Assets/EUFramework/Extension/EURes/` → `EUFramework.Extension.EURes`
- `Assets/Plugins/ResKit/` → `Plugins.ResKit`
- `Assets/Tools/ResourceManager/` → `Tools.ResourceManager`
- `Assets/ResKit/` → `ResKit`

**模板文件**：
- `Editor/Templates/DefaultResKit.cs.sbn` - 已使用 `{{ namespace }}`
- `Editor/Templates/DefaultResKit.Generated.sbn` - 修改为使用 `{{ namespace }}`
- `Editor/Templates/ResKitUserOpePopUp.cs.sbn` - 已使用 `{{ namespace }}`

### 5. 新增管理工具

**位置**：ResKit 配置工具 → ResFacade 面板 → 模块管理工具

#### 🔄 刷新命名空间
**功能**：
- 自动检测模块当前位置
- 根据路径计算正确的命名空间
- 更新 `EURes.asmdef` 和 `EURes.Editor.asmdef` 的 `rootNamespace`
- 可选择重新生成所有代码文件

**使用场景**：
- 将模块移动到新位置后
- 初次集成到新项目
- 命名空间需要更新时

#### 🗑️ 删除所有生成的文件
**功能**：
- 清理所有生成的代码和资源文件
- 两种模式：
  - **仅删除代码和UI**：保留配置文件（推荐）
  - **完全清理**：删除包括配置在内的所有生成内容

**删除清单**：
```
代码文件：
  ├─ Script/ResKit.cs
  ├─ Script/ResKit.Generated.cs
  ├─ Script/ResKitUserOpePopUp.cs
  └─ Script/Generated/ (整个文件夹)

UI 资源：
  └─ Resources/ResKitUI/ResKitUserOpePopUp.prefab

配置文件（可选）：
  └─ Resources/ResKitSettings/
      ├─ AssetBundleCollectorSetting.asset
      ├─ ResKitPackageConfig.asset
      ├─ ResServerConfig.asset
      └─ YooAssetSettings.asset
```

## 🎮 使用指南

### 首次使用
1. 确保已安装 YooAsset 和 UniTask
2. 打开 ResKit 配置工具
3. 生成 UI 和代码文件
4. 查看底部显示的当前命名空间

### 迁移到新项目
1. 复制整个 `EURes` 文件夹到新项目任意位置
2. 打开 ResKit 配置工具 → ResFacade 面板
3. 点击 "🔄 刷新命名空间"
4. 选择是否重新生成代码
5. 完成！

### 清理重置
1. 打开 ResKit 配置工具 → ResFacade 面板
2. 点击 "🗑️ 删除所有生成的文件"
3. 选择删除范围
4. 确认删除

## ⚠️ 注意事项

### 编译相关
- 新创建 `ResKitPathHelper.cs` 后，Unity 会自动编译
- 如果看到编译错误，等待 Unity 完成编译即可
- 刷新命名空间后，建议重新生成所有代码文件

### 路径相关
- 模块必须包含 `EURes.asmdef` 文件（用于定位根目录）
- 必要的文件夹结构：`Editor/`, `Script/`, `Resources/`
- 不要修改 `EURes.asmdef` 的文件名

### 命名空间相关
- 命名空间根据文件夹路径自动生成
- 移动模块后记得刷新命名空间
- 代码中的 using 语句需要使用新的命名空间

## 🔧 技术细节

### 路径查找机制
```csharp
// 通过 AssetDatabase.FindAssets 查找 EURes.asmdef
string[] asmdefGuids = AssetDatabase.FindAssets("EURes t:asmdef");
// 从 asmdef 位置确定模块根目录
_moduleRoot = Path.GetDirectoryName(asmdefPath);
```

### 命名空间计算
```csharp
// 移除 Assets/ 前缀
string withoutAssets = root.Replace("Assets/", "");
// 将路径分隔符替换为点号
_namespace = withoutAssets.Replace("/", ".").Replace("\\", ".");
```

### asmdef 更新
```csharp
// 使用字符串替换更新 rootNamespace 字段
lines[i] = $"    \"rootNamespace\": \"{newNamespace}\",";
```
